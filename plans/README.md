## Findings considered and rejected

- **`TimeProvider` injection to kill ~18 `DateTime.Now` sites** (ItemManager,
  SessionCacheManager, SchoolService, Login/Admin handlers): worthwhile but
  a production refactor, not a tests prerequisite — plans 002/003 assert
  ordering, not wall-clock values. Revisit when a feature actually needs
  deterministic time (lockout windows, session expiry).
- **Making the app's DbContext provider config-driven**: WAF can swap the
  provider via `RemoveAll<DbContextOptions>` without touching Program.cs; a
  `Database:Provider` config key is unnecessary surface. Rejected for now.
- **Hardening `SessionCacheManager` concurrency (plain `Dictionary` in
  singleton cache) and re-checking lockout mid-session**: real, but a
  behavior change outside test scope; the per-class-factory test design
  sidestops it. Track separately if admin lockout tests flake.
- **Fixing `TrackViewAsync`'s concurrent-duplicate race on main**: fix lives
  on unmerged `feature/wcag-2.2-aa` (`817cb61`); plan 002 notes the follow-up
  test for when it merges.
- **CI on `release` branch / deploy gating**: deploy.yml stays as is; the
  new build-test workflow gates PRs and main, which is where regressions
  enter.
- **Cleanup batch (unused `Faker.Net` package, dead
  `BookerIdentityDbContextConnection` string, dead `testingPhase` flag,
  unused `IpRateLimitAllMethods` policy, README's stale Blazor claim)**:
  real observations from the audit, none block the test plans; fold into a
  future chore PR.
